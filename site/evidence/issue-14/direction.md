# Issue #14 homepage direction

Scope: Chinese and English product homes only. Visitor mode: Persuade. The audience is Resolve editors deciding whether to install Clackly, with extension authors as a second path.

## Direction contract

THESIS: Stay in the edit. A large, real command palette sits over an explicitly schematic edit; product evidence carries the first impression.

OWN-WORLD: The existing Palette is the color authority: #151619 graphite, #e7e8ea light neutral actions, neutral type and fine translucent white edges. Keep the unchanged R1 cat icon and HarmonyOS Sans. An original silver edit-aperture light study creates directional light, falloff and a fine illuminated edge around the hero. Dark framed product theatre, open alternating feature rows and a dark AI workbench carry the same material. Documentation keeps Black Theme.

STORY: Recognize a keyboard-first Resolve palette, see Launcher/search and an illustrative Extension View, then download v0.1.6 or build a tool with the official Developer Skill. No invented capabilities, testimonials or speed claims.

FIRST VIEWPORT: Quiet framed navigation; a large centered statement inside a directional silver light arc; short product definition and official Windows download; a 1200px dark demonstration stage with a 334px real palette, fine rim light and soft depth shadows. Phones recompose the stage around a centered 250–270px palette. Signature interaction: keyboard-accessible Launcher/Search screenshot switching.

MOTION: The user requested the halo's entrance and scroll-triggered content reveals, then clarified a lower-right → up the right side → leftward path and a slower pace. The original inline HomeLight.astro draws five layered SVG strokes over 4000ms with symmetric ease-in-out; ambient light settles in the same sequence. Text, download actions and the product stage stay stable. Scroll reveals group the section introduction, each product row, extension note, AI workbench and closing. Product rows rise 28px and resolve 3px of blur; text moves 16px without blur; the AI panel uses 20px/2px. Opacity/blur settle over 1050ms and position over 1300ms, with a softer ease-out, once per group. No sibling-by-sibling delays, loops, scroll listeners or motion dependency. A single IntersectionObserver enhances content that starts readable; keyboard focus reveals immediately. Reduced motion retains the full static light and content; unavailable JS/observer leaves content fully readable. The user prefers refreshing the live preview over receiving recordings.

FORM: User-pinned product presentation reference, Raycast; translated into Clackly's own assets and Resolve context. Code-led candidate for final user visual acceptance, without an image comp. seed: none (user-pinned direction).

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

## Acceptance boundary

The initial flat warm stage and light feature cards were rejected for lacking the reference's lighting and material depth. After the light-based revision, the user explicitly selected “首页适配现有主界面”: keep the improved depth, align the homepage to the existing Palette color system, and keep application UI and icon redesign outside this task. This selects the color direction, not final visual acceptance.

Issue #14 and the current request authorize implementation, screenshots, a PR and an Issue handoff. The user viewed the revised live preview and gave positive feedback on the Palette-aligned colors and final motion (“效果不错”). Retain this candidate; no merge or Pages publication is authorized. This candidate uses a local browser preview; official Pages continues to show the accepted baseline.
